# Frontier-lab and large multimodal data practice: what a catalog would have to do (state as of 23 Nov 2026)

Scope: public evidence about how frontier AI labs and large video/embodied/autonomy data shops manage training and evaluation data, and what that implies for an open-source multimodal data catalog (dataset = table of samples with pointer cells; immutable file versions with checksummed replicas; PROV-style provenance; licence/consent/takedown propagation; Postgres core).

## 1. What public sources reveal about frontier-lab data platforms

### Takeaway
Labs run two distinct data estates. (a) A conventional lakehouse (Spark, Kafka, Flink, Iceberg/Delta, Trino, Airflow) at hundreds of PB to "multiple exabytes", used for product telemetry, logs, analytics and increasingly RL transcripts. (b) A research/training data estate (crawl, tokenized shards, multimodal blobs, human data, RL environments) that is far less publicly described and is where the hiring for "dataset management, cataloging, provenance tooling" is happening. Video-generation labs have converged publicly on Lance + Ray; LLM labs have not disclosed their training-data table format.

### Inferences
- [INFER] The Iceberg/Spark lake is the system of record for *events and logs*; the training corpora (tokenized shards, media blobs) live beside it in object storage with lab-specific indexing. Nothing public shows any LLM lab using Iceberg/Unity as the catalog of training shards. A catalog aimed at labs must therefore federate with, not replace, an Iceberg REST catalog.
- [INFER] "Convergence toward canonical datasets, including the core data model for RL transcripts" (Anthropic) means agent/RL trajectories are now a first-order dataset type that lacked a canonical schema as recently as 2026.
- [INFER] Both Anthropic and OpenAI are hiring for catalog/provenance/lineage tooling in 2026, which is direct evidence that this layer is homegrown and incomplete.

## 2. Workload shapes the catalog must serve

### Takeaway
Nine recurring shapes, each with a different unit of addressing: web documents (URL + crawl time), licensed deliveries (contract + batch), human-data tasks (campaign + worker + rubric), model-generated rows (generator model + prompt + seed), RL/agent transcripts (environment + episode + step), eval items (benchmark + item + canary), token shards (shard + offset), video/audio clips (asset + time span), and sensor logs (log + topic + time range). Video and robotics both converged on "many logical units packed into few large files, addressed by metadata offsets".

[SNIP] https://blog.glennklockwood.com/2025/02/llm-training-without-parallel-file.html . Staged filtering with classifiers is in xAI and Anthropic postings (above). [SNIP] https://www.anthropic.com/legal/model-training-notice ; https://support.claude.com/en/articles/8896518

### Inferences
- [INFER] The "pointer cell = (file version, byte range | frame/time span)" model is exactly what LeRobot v3, Lance blob columns, MCAP chunk indexes and token shards all implement privately. The catalog's addressing scheme must cover: byte range, row range, frame index range, presentation-timestamp span (video frame-accurate addressing needs codec/GOP awareness), and (topic, log-time range) for sensor logs.
- [INFER] Derived columns accrete continuously (Runway quote). Cheap column addition/backfill without rewriting blobs is a hard requirement for the table layer; a catalog that models a dataset version as an immutable file list will be too coarse.
- [INFER] Mining ratios are extreme (Waymo <0.03%; Cosmos 20M h -> 100M clips), so most catalog traffic is selection queries over embeddings/metadata, not blob reads.

### Gaps
- No public description of how any lab stores token shards or tracks shard -> source-document lineage.
- Tesla numbers are 2021-2023 era; nothing current.

## 3. Mixture / recipe management

### Takeaway
The mixture is a first-class *named object* only in open research frameworks (SeqIO, OpenVLA/Octo mixture dicts, LeRobot aggregations), where it is code in a registry: a name mapping to (task, rate) pairs, nestable, with no intrinsic version, no data snapshot pinning, and reproducibility dependent on deterministic tasks. No lab has publicly described a versioned mixture registry. Vendors (Lance) offer snapshot tags, which pin data but not the weights/sampling recipe.

### Cited findings
- **SeqIO** README: "you can define `Mixture`s that will combine the examples from them according to some specified rate"; three ways to give rates (explicit per task, constant default, or a function evaluated at runtime such as `seqio.mixing_rate_num_examples`); "You can also include `Mixture`s in your `Mixture`"; mT5 uses a mixture of per-language tasks with tail languages up-weighted; mixtures are deterministic only "by using either deterministic tasks or using dataset checkpointing (and not running more than an epoch) for a non-deterministic task"; offline caching via `CacheDatasetPlaceholder`, but "Caching stochastic SeqIO Mixtures in this way is not supported"; tasks carry version only by naming convention (e.g. `wmt_t2t_ende_v003`); for eval, "each sub-Task is evaluated separately, regardless of mixing rates". [FULL] https://github.com/google/seqio/blob/main/README.md
- T5X paper: seqio creates reproducible "tasks"; mixtures referenced by name from gin configs. [SNIP] https://arxiv.org/pdf/2203.17189
- **OpenVLA** `mixtures.py`: a Python dict `OXE_NAMED_MIXTURES` mapping names ("bridge", "rtx", "oxe_magic_soup", ...) to lists of `(dataset_name, sampling_weight)`, with hand-tuned weights such as `("fractal20220817_data", 0.54087122203)`, `("kuka", 0.8341046294)`, `("berkeley_cable_routing", 3.0)`, and dataset variants identified by ad hoc names like `..._converted_externally_to_rlds`. [FULL] https://github.com/openvla/openvla/blob/main/prismatic/vla/datasets/rlds/oxe/mixtures.py
- **Apertus 1.5** (arXiv 2610.15542) describes a public repository recording "each source's pinned revision, download script, processing recipe, license filters, and training stages", i.e. an open model treating the recipe as a published artifact. [SNIP] https://arxiv.org/pdf/2610.15542
- **Lance/LanceDB**: tags pin a snapshot; docs say "data versions and tags make it possible to tie a checkpoint back to the exact rows and features used for training"; branches and shallow clone; a May 2026 post "Reproducible data curation in the multimodal lakehouse". [SNIP] https://lancedb.com/blog/reproducible-data-curation-in-the-multimodal-lakehouse ; https://www.lancedb.com/blog/branching-and-shallow-clone
- **Cosmos Curator Next** calls its pipeline definitions "recipes" with data "contracts" and a pipeline-kind registry. [FULL] (repo above)
- **Meta** lineage collection includes "training manifests" as a lineage signal source (Oct 2025 PAI post). [SNIP] https://engineering.fb.com/2025/10/23/security/scaling-privacy-infrastructure-for-genai-product-innovation/
- System cards / legal notices describe sources and handling in prose only (public web via crawler, licensed, opted-in user data, synthetic; dedup and classification). No mixture proportions are disclosed by any lab. [SNIP] https://www.anthropic.com/legal/model-training-notice
- RLDS/Reverb: RLDS defines the episode/step schema and Reverb the sampling table with rate limiters; neither versions a mixture. [PRIOR; RLDS README fetched but not mined in detail] https://github.com/google-research/rlds

### Inferences
- [INFER] What a first-class mixture object needs, derived from the above: (1) immutable identity and version; (2) components = pinned dataset *versions* (or other mixtures) with weights; (3) weight semantics declared (per-example rate vs proportional-to-size vs temperature-scaled; SeqIO allows runtime functions, so the *resolved* numeric weights must be recorded at materialization time); (4) per-component filter/transform chain with code version; (5) sampling spec (seed, with/without replacement, epoch policy, curriculum schedule over steps); (6) the materialized outcome (shard list + per-shard source counts) as a separate, checksummed entity; (7) a `used` edge from each training run to the mixture version and, ideally, the realized consumption (which shards/steps were actually read before the run stopped).
- [INFER] Because rates can be functions of cached statistics, "reproduce the mixture a year later" fails unless the catalog stores the resolved weights and the dataset snapshots, not the code that computed them.
- [INFER] Mixtures also serve as eval suites (SeqIO evaluates each sub-task separately), so one object type with a "purpose" attribute covers both train recipes and benchmark suites.

### Gaps
- No public evidence at all on how OpenAI, Anthropic, DeepMind, xAI or Meta define or version training mixtures. Everything about labs here is inference.

## 4. Governance and security requirements

### Takeaway
Litigation and regulation have turned four catalog questions into legal obligations: "what is in dataset X and where did it come from", "search all training data for these works", "prove this was deleted (or preserved) everywhere", and "publish a summary of sources". Public filings show labs struggling with each.

### Cited findings

**Discovery, preservation, deletion**
- NYT v. OpenAI: 13 May 2025 order to preserve all output logs that would otherwise be deleted (incl. temporary chats, API outputs); ended by stipulated order of 9 Oct 2025 effective 26 Sep 2025; already-segregated logs stay held; EEA/Swiss/UK users exempt; accounts flagged by NYT still retained. [SNIP] https://engadget.com/ai/openai-no-longer-has-to-preserve-all-of-its-chatgpt-data-with-some-exceptions-192422093.html
- Training-data inspection: plaintiffs' experts searched OpenAI training data on two provided VMs for 150+ hours from 1 Nov 2024; on 14 Nov 2024 OpenAI engineers erased search data on one VM; recovered data lost "folder structure and file names" so could not be used to determine where articles ended up in training datasets. [SNIP] https://techcrunch.com/2024/11/20/openai-accidentally-deleted-potential-evidence-in-ny-times-copyright-lawsuit/
- July 2026 sanctions motion (In re OpenAI Copyright Infringement Litigation, 25-md-03143 SDNY) alleges two years of misrepresentations about OpenAI's ability to search training datasets and logs. OpenAI's 14 Aug 2026 opposition: it is "a technical reality" that its "existing tools can't execute searches across all training datasets and output logs for publishers' articles". No ruling found. [SNIP] https://news.bloomberglaw.com/litigation/openai-says-ny-times-seeks-sanctions-due-to-lack-of-evidence ; https://www.aljazeera.com/economy/2026/7/9/nyt-led-group-asks-court-to-sanction-openai-in-us-copyright-dispute
- OpenAI deleted its "Books1"/"Books2" datasets (built from LibGen) in 2022, stated reason "non-use"; Magistrate Judge Wang (24 Nov 2025) held privilege over the deletion reasons waived; crime-fraud exception not found. [SNIP] https://www.hollywoodreporter.com/business/business-news/openai-loses-key-discovery-battle-why-deleted-library-of-pirated-books-1236436363/
- Bartz v. **Safety filtering and supply chain**
- LAION-5B: Stanford Internet Observatory (Dec 2023) found 3,000+ suspected CSAM links; dataset withdrawn; Re-LAION-5B (30 Aug 2024) removed 2,236 links matched against partner hash lists; LAION publishes metadata so third parties can "clean existing copies"; SIO recommended deprecating models trained on the original. This is the canonical takedown-propagation case: a removal list that must be applied to every downstream copy and derived dataset. [SNIP] https://laion.ai/blog/relaion-5b/ ; https://purl.stanford.edu/kh752sm9123
- Poisoning: Carlini et al. (IEEE S&P 2024): $60 could have poisoned 0.01% of LAION-400M/COYO-700M via expired domains (split-view) and Wikipedia snapshot frontrunning; defence is distributing cryptographic hashes so consumers see what the maintainer indexed. [SNIP] https://arxiv.org/abs/2302.10149 . Anthropic/UK AISI/Turing (Oct 2025): ~250 poisoned documents backdoor models from 600M to 13B parameters regardless of corpus size. [SNIP] https://www.anthropic.com/research/small-samples-poison
- Exfiltration: RAND "Securing AI Model Weights" (30 May 2024): 38 attack vectors, SL1-SL5; recommendations include centralising all copies in access-controlled monitored systems and reducing the number of authorised people; follow-ons: SL3 control set (262 controls mapped to NIST 800-53) and an "algorithmic insights" report with 44 vectors. [SNIP] https://www.rand.org/pubs/research_reports/RRA2849-1 ; https://www.rand.org/pubs/research_reports/RRA4704-1.html . Anthropic ASL-3 (May 2025): egress bandwidth controls on environments holding weights, two-party authorisation, binary allowlisting. [SNIP] https://anthropic.com/news/activating-asl3-protections
- Eval secrecy: FrontierMath (Dec 2024-Jan 2025): OpenAI funded and had access to problems and solutions except a 50-question holdout, under only a "verbal agreement" not to train on it. [SNIP] https://epoch.ai/blog/openai-and-frontiermath . Canary strings: LessWrong reports the BIG-bench canary is reproduced by Gemini 3 Pro and Claude Opus 4.5 (unverified blog claim), i.e. canary filtering is leaky in practice. [SNIP] https://www.lesswrong.com/posts/QYdNfqfFAeMHXTHkP/reasons-to-care-about-canary-strings

### Inferences
- [INFER] "Search across all training datasets" is a required capability, not a nice-to-have: a content-addressed index (exact hash + near-duplicate fingerprint + source URL/identifier) spanning every dataset version, including derived/tokenized forms, with results mapped back to source rows.
- [INFER] Legal state is multi-valued per sample: acquisition channel (crawl/licence/purchase-and-scan/user/vendor/synthetic), acquisition jurisdiction and time, robots/opt-out state at crawl time, licence id with permitted-use set {pretrain, finetune, eval, RAG, display} and term, consent state, takedown state, legal-hold state. Holds and deletions conflict (Bartz: destroy "subject to preservation obligations"; NYT: preserve what users deleted), so the catalog needs both tombstone and hold semantics with a precedence rule and a segregated-retention location.
- [INFER] Deletion must be provable across replicas (per-replica deletion receipts) and must enumerate derived artifacts (shards, embeddings, caches). Deletion reasons need an auditable record (Books1/2).
- [INFER] Compute location is a legal fact (Getty). Runs should record where data was read and where training executed.
- [INFER] The EU summary is an aggregation query (bytes by registrable domain, by acquisition channel, by collection window, by modality) over provenance columns; if those columns exist the report is a view.
- [INFER] Eval sets need a distinct protection class: never-train flag enforced at mixture resolution, canary registry, contamination scans of every candidate training set against the eval index (exact and fuzzy), access logs, and third-party-held holdouts whose existence is cataloged without content.
- [INFER] Integrity: recording content hashes at index time and verifying at materialization is the published defence against split-view poisoning; the catalog's immutable versions + checksums give this for free if URL-list datasets are stored as (url, hash-at-crawl).

### Gaps
- No public description of internal access tiers/compartmentalisation for training data at any lab (only weights). Take It Down Act / NCII training-data specifics not found.
- Reddit licence deletion mechanics not public beyond the complaint's characterisation.

## 5. Performance requirements

### Takeaway
Published designs agree: the metadata/control path must stay out of the data path; data must be staged or cached next to GPUs (regional object stores, node-local NVMe, even GPU-memory caches); cross-region/cross-cloud movement is now a product feature (Meta, CoreWeave). The catalog's job is to know where replicas are and to resolve pointers to the nearest one, then get out of the way.

### Cited findings
- **Meta, "Meta's AI storage blueprint at scale" (1 Jul 2026):** hundreds of exabyte-scale clusters; storage bottlenecks "remain a major cause of GPU stalls"; old BLOB path proxied reads through API servers; replaced by a fat-client SDK streaming directly from Tectonic; "regional BLOB stacks colocated with GPUs in every AI region"; flattened metadata schema (ZippyDB); spare GPU memory used as a distributed cache (~80% hit rate per a secondary source); up to 97% cut in time to move training data across regions (secondary). [SNIP] https://engineering.fb.com/2026/07/01/data-infrastructure/metas-ai-storage-blueprint-at-scale/ ; https://www.datacenterdynamics.com/en/news/meta-rebuilds-its-ai-storage-stack-from-the-ground-up-to-stop-gpus-sitting-idle/
- Meta DSI (2021-22): ingestion pipeline at "tens of terabytes per second"; storage + preprocessing can consume more power than the GPU trainers; disaggregated Data PreProcessing service (DPP). [SNIP] https://arxiv.org/abs/2108.09373 ; https://engineering.fb.com/2022/09/19/ml-applications/data-ingestion-machine-learning-training-meta/
- **Lockwood, "LLM training without a parallel file system" (Feb 2025):** very large LLM training uses object storage; stage inputs to node-local NVMe; checkpoint size scales with the model not the cluster; HDD-backed Azure Blob benchmarked at 1+ TB/s writes. [SNIP] https://blog.glennklockwood.com/2025/02/llm-training-without-parallel-file.html ; https://www.blocksandfiles.com/ai-ml/2025/02/04/very-large-ai-model-training-uses-object-storage/1602990
- **CoreWeave AI Object Storage / LOTA (16 Oct 2025):** caches on GPU-node NVMe; "up to 7 GB/s per GPU ... regardless of where the data is located"; cross-region GA, multi-cloud/hybrid promised for early 2026; no egress/request fees; "Zero Egress Migration" pays hyperscaler egress for initial moves. [SNIP] https://investors.coreweave.com/news/news-details/2025/CoreWeave-Unveils-AI-Object-Storage-Redefining-How-AI-Workloads--Access-and-Scale-Data-2025-134hIiFR9N/default.aspx
- Multi-site compute: GPT-5.5 trained at Stargate Abilene on OCI (OpenAI post); OpenAI capacity spans Azure, Oracle, CoreWeave, AWS; Spark runs on Azure and AWS. [SNIP] https://openai.com/index/building-the-compute-infrastructure-for-the-intelligence-age/ . Anthropic data-infra posting spans GCP and AWS.
- Runway: training on "tens of thousands of GPUs directly from Lance tables" (vendor-relayed). Wayve: 50x gain in training data throughput on Azure (Microsoft customer story). [SNIP]
- Ray Data on CoreWeave: 600 GB -> 600 TB synthetic video in 95 min (vendor demo). [SNIP] https://coreweave.com/blog/video-captioning-at-scale-600-tb-in-95-minutes-with-anyscale-on-coreweave
- Small-scale public write-ups: streaming 20 TB tokenized shards from S3 to 160 H100s with prefetch. [SNIP] https://krish-mahajan.github.io/blog/streaming-architecture/

### Inferences
- [INFER] Catalog call pattern must be "resolve once per shard/epoch, in bulk", never per sample: batch pointer resolution returning (replica URL list ranked by locality, byte ranges, checksums, short-lived credentials). At 10^4-10^5 GPUs a per-sample Postgres lookup is impossible; manifests must be exportable as immutable files (Parquet/Lance) that loaders read directly, with the catalog authoritative for identity and placement.
- [INFER] Replica placement is a first-class operation: "ensure dataset version V is present and verified at site S before job J starts", with transfer state, partial-replica accounting, cost (egress) estimates and expiry of cache replicas. This is the Rucio rule model applied to GPU sites, and it is exactly what Meta and CoreWeave built privately.
- [INFER] Cache tiers (node NVMe, GPU-memory cache) are ephemeral replicas the catalog should not track individually, but durable regional copies must be tracked and checksummed.

### Gaps
- No public numbers for cross-cloud dataset transfer volumes or egress spend at any lab. No published loader throughput for LLM pretraining at 10^5 GPUs.

## 8. Requirements for a catalog serving these users (each tied to evidence)

R1. **Global content search across every dataset version**, exact and near-duplicate, returning source rows and all derived locations. Evidence: OpenAI's "technical reality" filing (Aug 2026); 2024 inspection incident; Bartz/Books1-2 need to enumerate copies.
R2. **Sample-level identity that is stable across repackaging** (content hash + source id), so dedup across sources and lineage through tokenization/sharding survive. Evidence: Anthropic pretraining posting (dedup/chunking/tokenization); Cosmos Curator "identity" utilities in flux; Xet/CDC shows chunk-level identity works at 10+ PB.
R3. **Pointer cells covering byte range, row range, frame/PTS span, and (topic, time range)**, into immutable file versions. Evidence: LeRobot v3 offsets-into-shared-files; MCAP chunk index; Cosmos 100M clips from 20M hours; Lance blob tables.
R4. **Cheap additive columns and dataset versions as snapshots over shared blobs**, not file-list copies. Evidence: Runway "a training example doesn't stay still"; Iceberg backfill complaint; Netflix Media Table.
R5. **First-class versioned mixture/recipe object** with pinned component versions, resolved numeric weights, filter chain, sampling/curriculum spec, seed, and a separately recorded materialization; nestable; usable for eval suites. Evidence: SeqIO semantics and its determinism caveats; OpenVLA hand-edited dict; no lab disclosure; Lance tags pin data only.
R6. **Run-to-data lineage with realized consumption**: run `used` mixture version (role: train/eval/validation), plus which shards/steps were actually read. Evidence: Meta "training manifests" as lineage source; Voxel51 "which data went into a model"; Anthropic "pipelines that extract data from training runs".
R7. **Legal-state model per sample and per source**: acquisition channel, jurisdiction, time, crawler/robots state, licence with permitted-use set and term, consent tier, retention class. Evidence: licence drafting guidance (training vs grounding vs display); Reddit terms; Anthropic consumer terms (5-year vs 30-day); Bartz (purchased-scan vs pirated).
R8. **Takedown/deletion propagation along lineage with per-replica proof, plus legal holds that override deletion and route to segregated retention.** Evidence: Re-LAION removal lists; Reddit deletion compliance; Bartz destruction "subject to preservation obligations"; NYT preservation order and its Sep 2025 unwind; Books1/2 privilege fight over deletion reasons.
R9. **Policy enforcement at mixture resolution time** (purpose limitation): block or flag a recipe that includes never-train, expired-licence, opted-out or held data. Evidence: Meta Policy Zones/PrivacyLib (log, block, reroute); FrontierMath "verbal agreement".
R10. **Eval-set protection class**: never-train flag, canary registry, standing contamination scans (exact + fuzzy) of training candidates against eval index, access audit, catalog entries for externally held holdouts. Evidence: canary leakage reports; contamination survey; Runway "decontamination" stage; FrontierMath.
R11. **Regulatory reporting as queries**: EU Art. 53(1)(d) summary (top 10% domains by bytes, crawler names, collection periods, licensed/user/synthetic breakdown). Evidence: template of 24 Jul 2025.
R12. **Replica placement and movement as managed state**: rules of the form "version V verified at site S by time T", transfer tracking, locality-ranked resolution, egress cost awareness, cache-replica expiry. Evidence: Meta regional BLOB stacks and 97% faster cross-region moves; CoreWeave LOTA cross-region/cross-cloud; OpenAI Spark on Azure+AWS and training on OCI; Anthropic GCP+AWS; Getty (location matters legally).
R13. **Catalog off the hot path**: bulk manifest export and batch pointer resolution; loaders read immutable manifest files and nearest replicas directly. Evidence: Meta removing the API-server proxy from the read path; Lockwood on object storage + local NVMe; 7 GB/s per GPU class numbers.
R14. **Integrity verification at materialization** (hash recorded at index time, checked at read/pack time) and source-trust metadata. Evidence: Carlini split-view attack and hash defence; 250-document backdoor result.
R15. **Access compartments and exfiltration-aware audit**: tiered access per dataset/eval set, two-party approval for bulk export, read-volume anomaly logging. Evidence: RAND SL3-SL5 recommendations; Anthropic ASL-3 egress controls (for weights; applying them to data is inference).
R16. **Human-data and synthetic-data provenance as typed activities**: campaign, vendor, worker pseudonym, rubric version, QA outcome; generator model id, prompt/template version, seed, parent samples. Evidence: OpenAI/Anthropic Human Data orgs; synthetic contamination paths; distillation incidents.
R17. **Canonical trajectory/episode schema support** (environment, episode, step, tool calls; multi-sensor time alignment for robots). Evidence: Anthropic "core data model for RL transcripts"; RLDS; LeRobot v3; Generalist 270k+ hours.
R18. **Federation with existing lakehouse catalogs and formats** (Iceberg REST, Lance namespaces, MCAP stores, HF repos) by registering them as physical forms. Evidence: universal Spark/Iceberg stack per postings; Lance adoption at video labs; nobody will migrate exabytes.
R19. **Scale envelope**: 10^4-10^5 datasets, 10^11 rows per table, 10^2-10^3 PB per estate, discovery usable by agents. Evidence: OpenAI 70k datasets/600 PB and data agent; LanceDB 100B rows; Wayve hundreds of PB; Tesla 200 PB cache target.
R20. **Embedding/semantic indexes as derived, swappable artifacts tied to model version**. Evidence: Wayve model-agnostic embedding search; Tesla triggers; Waymo <0.03% mining ratio.
